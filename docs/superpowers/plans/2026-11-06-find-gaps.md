# Find Gaps Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `find-gaps` mode to the `progressive-ux-design` skill that finds missing pages and missing behaviors, interviews the user on each candidate, and offers to design the missing pages.

**Architecture:** One new procedure file (`find-gaps.md`) routed from `SKILL.md`. It reuses the survey rules in `evaluate-flows.md` by reference and the screen doc shape in `screen-template.md`. This is a prose skill, so each task is verified as `docs/status.md` records earlier work: baseline agents without the change, agents with it, plus grep checks.

**Tech Stack:** Markdown skill files, Claude subagents as test runners. No code.

**Spec:** `docs/superpowers/specs/2026-11-06-find-gaps-design.md`

## Global Constraints

- Skill files live in `skills/progressive-ux-design/` (the root symlink `progressive-ux-design-skills` points at `skills`; never edit through it).
- Flow only: no visual aesthetics. One layer per document; link by id, never copy.
- A gap becomes an Open question with `Origin: added` and `Resolve in: product` (values `high | low | persona | product`). Never invent.
- Survey rules come from `evaluate-flows.md` "Survey rules": interactive question tool, at most 4 questions per call, at most 3 readings plus Skip, Skip last, no recommendation that presumes intent.
- Technical gaps (network, exceptions, double-tap, offline, permissions plumbing) are never raised.
- Raw wireframes are read as is; this mode never converts them.
- New screen docs use `screen-template.md` ids (`El#`, `A#`, `SS#`) and go in `ux/screens/<id>.md` unless the user says otherwise. Fixtures, drafts and test outputs go only in `.superpowers/` (git-ignored).
- Stage changed files with `git add`; commit only through the commit proposal tool after the user approves.

## Review Focus

1. A page whose title repeats a link label ("Sign Up" in a header vs the title of `sign-up.md`): the title is not a candidate; the header link resolves to the doc.
2. A link to an external site or `mailto:`: not a missing page; expected: not raised.
3. A clean doc set with no gaps: expected zero candidates and no questions.
4. An entity with only one state (nothing to edit or publish): expected no behavior candidates.
5. The user answers "Missing page" for a target the docs imply nothing about: the drafted screen has open questions, not invented elements.

## Milestone 2: Missing behaviors and close-out

### Task 3: Missing-behaviors procedure

**Files:**
- Modify: `skills/progressive-ux-design/find-gaps.md` (`## Missing behaviors`, `## Order of a run`)

**Interfaces:**
- Consumes: Task 2's file and survey pointer.
- Produces: the five-step behaviors procedure from the spec.

- [ ] **Step 1: Write the failing check.** Extend `check-find-gaps.sh` to also require the strings `counterpart`, `one-sided`, and `no exit` in `find-gaps.md`. Run; expected FAIL.
- [ ] **Step 2: Write `## Missing behaviors`.** Entities and states are named only when a doc names them. The verb-by-state matrix lives in working notes, not the final doc. Candidates are absent cells in exactly three cases: a state-changing verb with other states unspecified; a one-sided pair (send without receive, create without delete, publish without unpublish); a state entered with no exit. Entities with one state yield no candidates. Question text is specific ("Can the user edit a published image?"), options are the plausible readings then Skip, answers apply as small corrections, Skip becomes an Open question. Technical gaps excluded.
- [ ] **Step 3: Write `## Order of a run`.** Pages first, then behaviors; one summary of candidate counts before the interview; nothing is asked about a part the user declined.
- [ ] **Step 4: Run the check.** Expected PASS.
- [ ] **Step 5: GREEN runs** on `art-app`, `email-app`, and `clean`. Expected: art-app finds edit, unpublish and delete after publish; email-app finds receive (counterpart role); clean yields zero candidates and asks no questions; no technical gaps raised in any run. Record gaps in `.superpowers/work/gaps-green/notes.md` and close each in `find-gaps.md`.
- [ ] **Step 6: Stage.** `git add skills/progressive-ux-design/find-gaps.md`
